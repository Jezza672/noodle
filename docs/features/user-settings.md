# User settings

Preferences that belong to the person, not the project, live in one settings file in the platform config directory (`prefs.ron`, `crates/noodle-app/src/prefs.rs`). Beat snap and the MIDI take quantise were the two that were forgotten at exit; they are now saved with the rest (audio devices, plugin sandbox, playback cache, count-in and pre-roll, MIDI record mode, automation mode, the display switches and the keymap).

- **Portable.** The settings that travel are all of them except the audio device choices, the monitor device and the plugin sandbox, which are about this machine (`Prefs::portable`).
- **Export and import.** The General tab of Settings has Export User Settings…, which writes the portable settings to a file, and Import User Settings…, which reads one. The import dialog also accepts a project file and takes the settings saved in it. An import replaces the portable settings and keeps this machine's devices.
- **In the project.** Every save writes the current portable settings into the project as `user_settings` (opaque text, which `noodle-core` stores but does not read; not an undo step, not part of equality, left out of templates).
- **Opening.** A plain Open never touches the user's settings. Open with Settings (File menu, Cmd/Ctrl+Shift+O, or Shift held on Open…) loads the project and then takes its settings as the user's own.

Tests: `prefs.rs`, and `app.rs` (snap remembered, a project carries settings but only Open with Settings takes them, export and import from a file and from a project, devices kept on import).

- **One Settings window** (`settings.rs`, File > Settings…, Cmd/Ctrl+,). The manager view: the first action for most things happens where it is needed (the Sounds panel's Add source menu, Create drum rack, Split to stems, View > Overlays), and Settings is where they are kept up. A search field and a vertical tab list on the left, a one-line description and the page on the right, in a window that keeps one size and place across tabs (tab rows are fixed-size; hover only recolours; a dot on a tab means a model is downloading or a source can't be reached). Tabs: *General* (plugin sandbox, import and export of user settings), *Audio* (`devices.rs`: output and audio input with a plain-words latency verdict, MIDI keyboards, and an Advanced fold with host, sample rate, buffer size, monitoring latency, output channels and worker threads; the Apply and Revert bar shows only while a device setting differs), *Display* (`display.rs`: a Full / Light / Performance preset row over the switches grouped as Wires, Meters and Nodes, each tagged with its cost; Performance mode and the CPU heat tint are also in View), *Models* (`models.rs`: one compact list of the drum and stem models, downloads start in the dialog that needs them) and *Sound sources* (`sounds/page.rs`: compact rows with a status dot, kind and a ⋯ menu; "+ Add source" opens a Web source popup that tests the address before closing, or goes straight to a folder picker). It replaces the separate Audio Settings and Display Settings dialogs and the Import/Export menu items. The audio devices, monitor device and plugin sandbox stay on this machine; they are left out of exported and project-embedded settings. Audio device changes apply with the Apply button; everything else takes effect as clicked.

## Settings redesign: follow-ups

- **Automatic worker threads (#578).** *Worker threads* now defaults to Automatic (`AudioConfig::threads` is `None`; a chosen count, including 0, overrides it). It resolves at stream start to every core but two, at most seven (`noodle_io::auto_threads`), and the dropdown's label says what it resolved to, for example "Automatic (2 extra threads)". The count depends on the machine, not the graph: the engine already checks each plan's shape (`Workers::worth`) and only uses the workers when the plan is wide enough, and idle workers sleep, so a graph that changes width needs no restart.
- **Tab icons and Show file.** Each tab in the list leads with a small glyph. General and Models have a *Show file* button that opens the folder holding the settings file or the model weights in the system file manager.
- **MIDI In keyboards.** Already built before the redesign: a MIDI In node's own panel lists the keyboards and marks a saved one that is missing "(not connected)" (`midi_ports::port_picker`).
- **Flaky tests folded in.** #584 (S09 route did not wait for the group's *Place on…* button, only the summary line) and #588 (the embedded-editor test could set its simulated drag between the plugin thread setting its own size and reading it back, which swallows the drag).
