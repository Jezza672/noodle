# Harmony and chance nodes

Issue #538. Chunk 1: the pitch nodes and the key on the transport. Chunk 2: the rhythm nodes, two templates and an example.

- **Scale Quantise, Chord, Transpose (events wire).** Parameters only, no config. Scale Quantise: `root`, `scale` (14 scales, Major 0 and Minor 1), `direction`. Chord: `type` (13 chords), `inversion`, `spread`, `strum` (0 to 100 ms across the chord, lowest note first). Transpose: `semitones` (-48 to 48). A note-on's result is remembered in `held_notes.rs`, so the note-off follows it whatever the parameters are now; a chord that does not fit the queue is dropped whole.
- **Song Key (`noodle.mod.key`).** A source node: `root`, `scale` and `shift` outputs from the timeline's key, with a `from` parameter for the key the part was written in. The outputs are the values themselves, which the whole-number parameters of Scale Quantise and Transpose take as they are, so no conversion node is needed (the choice the issue left to the implementer). `scale` reports major or minor only, because markers name only those; `shift` treats relative keys as equal, as clip Transpose does.
- **`Transport::key`.** From a `KeyTable` built by the controller and sent with the tempo table (`Tempos`). The Song Key node's cache key holds the project's key and every marker's.
- **Decisions.** Chord's strum delays only later notes, so the node reports no latency (as Swing); the issue suggested reporting latency like Humanise, but nothing needs holding back for an early note. Scale Quantise has no memory of its own: it keeps the note's ID, so a note-off needs nothing.

Tests: unit tests in each node file (note-off after a parameter change, held across it for Chord and Transpose); `tests/song_key.rs` renders a project whose marker changes the key and checks the outputs move at the marker; `tests/realtime.rs` runs all four in `busy_session`; `reset_matches_fresh.rs` covers every registered node. The S08 route has a late change, "transpose the part down a tone", with a Transpose node. Checked by breaking the code: a key table that ignores markers fails the marker test, and note-offs that use the current type or shift fail the Chord and Transpose held-note tests.

## Chunk 2: Euclidean, Chance and the templates

- **Euclidean (`noodle.event.euclidean`).** `steps`, `pulses`, `rotation`, `rate` (Clock's divisions, default 1/16), `gate`, `key`, `velocity`, `accent`. Bjorklund's pattern is a u64 bitmask built each block, no allocation; the spellings are the standard ones (E(3,8) is `x..x..x.`, E(5,8) `x.xx.xx.`), except E(3,4), which comes out `xxx.` (the same rhythm as `x.xx` turned). Rotation moves the pattern later. Steps are counted on the tick grid from the timeline's start, so the rhythm stays on the beat through seeks and loops; a jump of the playhead re-finds the next step. `steps`, `pulses` and `rate` are the featured parameters.
- **Chance (`noodle.event.chance`).** `probability` and `seed`. One draw per note-on, so seed and probability fully decide which notes pass; a note-off and expression follow their note-on.
- **Templates.** `Harmoniser`: Song Key, three Math nodes that blend the group's `root` and `scale` with the key's by `follow` (and gate the key's `shift` by it), then Transpose, Scale Quantise and Chord in a row; inputs `in`, `root`, `scale`, `type`, `follow`, `written in`. Presets Major Triads, Minor Sevenths and Follow the Key. `Euclid Hat`: Euclidean, Chance, Mono Note and the song kit's closed hat; inputs `steps`, `pulses`, `rotation`, `probability`. Presets Offbeat Five, Tresillo Eighths, Ghost Hat. Both are generated (`crates/noodle-eval/src/song/system.rs`) and embedded in `library/store.rs`. Each new node also has three node presets, because the library test wants two.
- **Example.** `examples/euclid-chords.ron` (480 bpm, so a quarter second holds the pattern): Euclidean into Chance, Transpose, Scale Quantise and Chord, all following a Song Key, with a marker that moves the song from D minor to G minor. Its golden render is `tests/golden/euclid-chords.wav` (seed 2 drops only the last hit; the chord changes pitch at the marker).

Tests: Bjorklund against the known patterns, hits on the grid, rotation, notes ending after their gate and a change, silence while stopped, accent; Chance at 0 and 1, repeatable per seed, a reset restarts the run, the held-off rule; `noodle-eval/tests/harmony_templates.rs` checks the templates work (the Harmoniser's chord pitch with and without following the key, the Euclid Hat's rhythm and silence at no pulses); the realtime test has Euclidean and Chance in `busy_session`. Checked by breaking the code: flipping the rotation sign fails the rotation test, and dropping the seed mix fails the Chance seed test. Routes: S15 (`euclid_route`, an Euclidean node gates the pad; late change "triplets" is the rate) and S09 (`euclid_route`, a hat from Euclidean and Chance); both read the patch, because the node is silent while the transport is stopped.
