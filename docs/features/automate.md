# Automate a parameter

"Automate and automation recording": the shortcut and ranges (issue #284), then recording (issue #285), both below.

- **The shortcut.** Right-click a parameter, choose **Automate** (`Edit::Automate`, built by `noodle-app/src/session/automate.rs`). One `Command::Batch`, so one undo step: an Automation node in the parameter's own group (so it works at any depth, a primitive inside a synth group too), placed to its left; a lane on the node's `value` with one point at tick 0; and a wire from `out` to the parameter. Nothing compiles differently: the parameter is an ordinary wired parameter. The entry is greyed, with a tooltip, on a parameter that already has a wire or a lane. It is offered in the graph and in the properties panel (`Automate` in `widgets/param.rs`).
- **The node copies, it doesn't link.** The Automation node has `min`, `max` and `taper` (Linear or Log) parameters, since they change no ports. `out` is `value` (0 to 1) mapped onto `min`..`max`; a log taper needs a positive range and otherwise falls back to linear. The defaults (0 to 1, linear) pass `value` through, so existing Automation nodes sound the same. Automate copies the range and taper once from the target, and the lane's point holds the target's current value as a position on that range, so nothing you hear changes.
- **Offsetting parameters.** A parameter whose wire *offsets* its value rather than replacing it (`ParamInfo::is_offset`, e.g. a filter's cutoff) takes the signal as a move along its travel, with 0 meaning no move. For these the node ranges over -1 to 1 and the lane starts in the middle (0.5, an offset of 0), so the parameter's own value stays the base and the sound is unchanged. This differs from "copy the target's range" in the roadmap text, which assumed a replacing wire: copying a cutoff's 20 to 20000 Hz would saturate the travel.
- **Name.** The node's `label` config (a text setting, editable in the properties panel) is set once to "Group › Parameter" (or "Node › Parameter" at the top level). The lane header shows it, falling back to "Automation N".
- **Tension per segment.** `Curve::Tension(t)`, `t` from -1 (exponential, slow start) through 0 (the straight line, the same as `Linear`) to 1 (S-curve). `Curve::shape` in `noodle-core/src/automation.rs` is the one shaping function, used by `AutomationLane::value_at` and the lane source (`noodle-engine/src/automation.rs`). It starts and ends exactly on its points and is monotone. Points travel in the lane source's config text as `t<value>`.
- **Lane editor.** Segments draw bent. Ctrl-drag (Cmd on macOS) a segment up or down to bend it; Shift-click picks several points, and bending one of their segments bends all of them alike, as one undo step. Hold segments stay holds.
- **Trim a range (#333).** Shift-drag on empty space in a lane picks a span of time; the points in it are marked. Dragging any marked point vertically moves all of them by the same amount (in dB on a gain lane, in the lane's own 0 to 1 value on an Automation node's lane, so not in the target's unit there; clamped to the lane's range). Right-click empty space in the lane with points marked for a **Trim** menu with a typed amount; `automation::trimmed` shifts the points in the span and keeps the lane's value at and just outside each edge as points of their own, so the shape outside is unchanged. Each is one `SetLane`, so one undo step. The trim is destructive: a later pass over the span replaces it.
- **Draw, pick, cut and move (#428).** Every lane has a small toolbar in its top right corner: **Points** (click adds a point, drag moves one, Shift-drag picks a span, as before), **Draw** and **Pick**; the tool is one setting for all lanes, and a line on the lane says what a drag does in the tool. With **Draw**, dragging across a lane paints a curve: each position the pointer crosses (snapped to the grid, Alt for free) becomes a point, and the points of the lane under the stroke are replaced (`automation::painted`; holds on a switch lane, lines elsewhere). The whole stroke is one `Edit::Drag` group, so one undo step. With **Pick**, a plain drag over empty space picks a span, as Shift-drag does. Right-clicking the picked span now offers **Trim** (a typed amount, as before), **Move** (slides the points along in time by a typed number of beats, `automation::slid`) and **Cut** (takes the points out, `automation::cut`); all keep the lane's shape outside the span by leaving points at its edges, as `trimmed` does, and each is one `SetLane`.
- **Map to (#353).** Drop a wire from an output (a group input, say) onto a parameter with Alt held: `Edit::MapTo` (`session/map_to.rs`) inserts a Remap between them in one `Command::Batch`, its output range set to the parameter's own range (-1 to 1 for an offset parameter) and its curve linear. One gesture per target; each target's range and curve are then edited on its own Remap. Refused on a parameter that already has a wire or lane.
- **Make external (#426, #425).** Right-click a parameter's port in the graph and choose **Make external**: `Edit::MakeExternal` (`session/make_external.rs`) adds a *variable* (an Automation node with no lane, a plain 0 to 1 knob, labelled "Param (macro)") and a Remap (the Map to gesture's, so the output range is the parameter's own, -1 to 1 for an offset parameter) between it and the parameter, in one `Command::Batch`. The variable's `value` is set to where the parameter's current value sits in that range (0.5 for an offset parameter), so nothing you hear changes. Wire the variable's `out` to more parameters with Alt (Map to) for a Remap each: that is also the route to one source driving several targets at different depths, since each Remap's range is its depth. Built only from primitives (Automation, Remap). Refused on a parameter that already has a wire or lane.

Tests: curve properties in `noodle-core` (endpoints exact, monotone, linear at zero tension); node mapping in `noodle-nodes/src/automation.rs`; the app test `session::automate::tests` automates a filter cutoff inside a group and checks the node, label, lane, wire, unchanged render and single undo; `timeline/automation_tests.rs` covers bending, multi-select, and range pick with a multi-point drag; `automation::trim_tests` covers the trim, a drawn stroke, cut and move; `automation_tests` drives the Draw tool and the Pick tool with its Cut menu; `session::map_to::tests` covers Map to; `session::make_external::tests` covers Make external (nodes and wires, unchanged value, refusal, single undo).

## Recording automation (#285)

`noodle-app/src/session/record_automation.rs` holds the `Recorder` (plain data fed with ticks, so it is tested without a clock); the session feeds it.

- **Arming** is per Automation node: a red dot in the node's header (where the monitor button sits on audio nodes) and on the lane header. `Edit::ArmAutomation`; session state, not saved, not an undo step. There is no global arm. An armed node records whenever the transport plays, not only under Record.
- **Modes** (`AutomationMode`): Read (nothing written, armed or not), Touch (writes while the node is moved or its `record` signal changes, goes back to the lane when let go) and Latch (writes from the first move to the end of the Pass, holding the last value). One mode for every node, under the arrow beside Record in the transport bar, saved in the app preferences (`automation_mode`). Nothing is written until the node is moved.
- **What records.** A `SetParam` of an armed node's `value` (from a drag or a typed value in the graph, the properties panel, or the slider on the lane header, which shows while armed) is taken by `Session::edit` while the transport plays: it is buffered and not applied. An Automation node's `value` field stays on the node when it has a lane: greyed and showing the lane when unarmed, live when armed.
- **The `record` input** is an ordinary parameter port on the Automation node, so wiring it makes the engine report its value like any wired parameter. While armed, `maintain` reads that value each frame and writes it as a move whenever it changes (Touch lets go after it has been still for half a beat). A `MIDI Control` knob records into the lane; an LFO is printed into it.
- **The Pass** runs from play to stop. Each frame the session feeds the playhead; a held value keeps being written while a stretch is open; a loop wrap or seek closes the stretch and, in Latch or while still held, opens another, so later cycles overwrite earlier ones. At the stop, `finish` splices each stretch into its lane (replacing the old points inside it), thins the recorded points to a tolerance of 0.004 of the lane's range, and makes one `Command::Batch` (a `SetLane` per node, an `AddLane` for an armed node with none). So **a Pass is one undo step**, however many nodes wrote. The audio thread gains nothing.
- **Heard as it is ridden.** While a node holds a value (a gesture, or Latch), the session sets the lane source's `live` and `live_on` parameters (`noodle_engine::LIVE`, `LIVE_ON`, on `lane_source_id(lane)`), and the source writes the held value instead of the lane. Letting go (Touch) or the end of the Pass sets `live_on` back to 0.

Tests: the recorder's modes, thinning, wrap and `record` handling in `record_automation.rs`; `session_tests` there ride a filter cutoff on the virtual output (one undo step, brighter render) and print an LFO into a lane through `record`.
