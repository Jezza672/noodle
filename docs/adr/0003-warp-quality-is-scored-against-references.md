# Warp quality is scored against references, not hand-set tolerances

Warp quality is measured by comparing warped audio with a reference: a native render of the same song at the target tempo where we generated the audio (known truth), and the output of established stretchers such as Rubber Band where we could not (borrowed truth). A real answer exists, and a tolerance taken from our own output only freezes whatever the method already does. So the committed baseline of metric numbers shows a before and after, and a CI threshold is a distance from the reference that must stay no worse than the worst reference stretcher's on the same material, never a number set just under today's results.

The metrics are phase-insensitive, because phase-sensitive ones fail on stretched audio: signal-to-error ratio correlated at only 0.1445 with listeners' scores, and a spectral distance (D_M) at 0.0274 ([Roberts and Paliwal, arXiv:2006.06153](https://arxiv.org/abs/2006.06153), section III.B). They are the paper's TSM features, checked against its published listening-test dataset before one is allowed to gate CI. Their MATLAB evaluation code is not used: it is unlicensed, needs MATLAB and an old PyTorch, and assumes constant speed.
