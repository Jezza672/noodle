# Tempo sync is a source node, not a mode on each node

Delay's `time` is in seconds and the LFO's `rate` is in hertz. To make either follow the project's tempo (#142) we add one primitive, **Tempo** (`noodle.mod.tempo`), instead of a `sync` setting on each node that has a time or a rate. Tempo has a `division` (1/4, 1/8, dotted and triplet values, and multiples of a bar) and two control outputs that follow the transport's tempo: `time`, the division's length in seconds, and `rate`, its reciprocal in hertz. Wire `time` into a Delay's `time`, `rate` into an LFO's `rate`, or either into anything else with a seconds or hertz parameter (a chorus, an envelope's length, a Lag).

A `sync` config on Delay and LFO was the other option in the issue. It would change what those nodes' parameters mean, give every future time-based node its own copy of the beat arithmetic and division list, and still leave a synth with no way to sync a node that did not get the option. One source node is the same pattern Clock already uses, keeps Delay and LFO as plain primitives, and lets a group expose just a `division` control. A synced echo and a synced tremolo are therefore groups (templates in the library), editable like any other.

The cost is that the tempo reaches a node as a signal that is constant within a block: a tempo change inside a block lands at the next block, like Clock and the Metronome, and a Delay whose `time` jumps with the tempo jumps in one step (a click on the echo's tail while the tempo moves; a tempo ramp is a staircase of block-sized steps, about 2.7 ms at the app's block). Putting a Lag between `time` and the Delay smooths this and is what the echo template does. Tempo is stateless, so a rebuilt copy picks up where the old one was, and it works while the transport is stopped (it reads the tempo at the transport's position, 120 bpm by default).

# The drum rack is a group template with empty slots

The Sampler (`noodle.instrument.sampler`) and Note Split (`noodle.event.note_split`) already exist (M9 batch B, #153), and the song kit builds a drum rack out of them, but no template in the library gave a user one. The Drum Rack template is that group with the samples left blank: eight slots on General MIDI keys (kick 36, snare 38, closed hat 42, open hat 46, clap 39, low tom 45, high tom 50, crash 49), each with `level`, `tune` and `pan` group inputs, and the Sampler's sample picked by the user per slot. It is a template, not a node, by the rule that instruments are groups of primitives. Samples are stored by content hash (ADR 0004), so a template cannot carry them; a slot without a sample is silent. The song kit's rack, whose slots are filled, stays as it is.
