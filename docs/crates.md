# Crates

What each crate is and which tests live where. The layering is in [ARCHITECTURE.md](ARCHITECTURE.md).

| Crate | What it is |
|---|---|
| `noodle-core` | Project document: graph, commands with undo, RON files. No DSP. `library/`: group templates, node and group presets, topology, the system and user stores; `library/system/*.ron` are generated (`UPDATE_LIBRARY=1 cargo test -p noodle-eval --test library`). |
| `noodle-engine` | Node API, compiler, plans, `Controller`/`Processor`, offline `render`. `doorbell.rs`: `Doorbell`, the real-time-safe way to wake a sleeping worker. `channels.rs`: `ChannelLayout` (mono to 7.1: speakers, pan gains, convert matrices). `spectral.rs`: the spectral wire's frames, `Analyzer` and `Synthesizer` (ADR 0007). |
| `noodle-macros` | `#[derive(Ports)]`: a node's `Layout` and port-index constants from one declaration. Re-exported as `noodle_engine::Ports`. |
| `noodle-nodes` | Built-in nodes, including the track input (`clip.rs`, which plays a track's audio clips). Integration tests: `realtime.rs` (also `Doorbell::ring` and `Bell::ring`), `idle_wakeups.rs` (an idle track input wakes no task), `thread_count.rs` (16 track inputs share the pools), `golden.rs`, `track_input.rs`, `track_input_realtime.rs`, `track_input_midi.rs`, `warped_clips.rs` (Repitch playback), `stretched_clips.rs` and `stretched_playback.rs` (Grain and Beats, offline and live), `benches/warp.rs` (stretcher speed), `midi_input.rs`, `spectral.rs` (whole graphs through Analyze and Synthesize), `offline_clips.rs`, `export.rs`, `m2_acceptance.rs`, `parallel.rs` (worker threads; counts allocations on every thread, so it is one test function), `profile.rs`. `render_project_with_clips` renders a project with audio clips offline. |
| `noodle-io` | WAV files, file decoding (`decode.rs`), transient detection (`onsets.rs`), resampling, waveform peaks and clip streaming from disk (`stream.rs`), the one audio-file change watcher (`files.rs`, `AudioFiles`), the shared background-task pools (`pool.rs`), device listing and choice (`devices.rs`, including the virtual output's ID), WAV and FLAC export writing (`export.rs`), output through cpal (`DeviceWriter`, `play`) and input (`input.rs`), MIDI input through midir (`midi.rs`: ports and the `MidiBus` the MIDI In nodes read). |
| `noodle-plugins` | Plugins can run in host processes (`sandbox/`; `tests/sandbox.rs` kills and freezes the host; `noodle-plugin-scan` is a host too). CLAP hosting through clack, AU hosting on macOS through AudioToolbox (`au/`, virtual `audiounit:<id>` files; `tests/au.rs` uses Apple's own units, `tests/au_unsupported.rs` checks the other systems) and VST3 hosting through the `vst3` bindings (`vst3/`; `examples/test_vst3.rs` is its test plugin, `tests/real_vst3.rs` uses real ones; install `dpf-plugins-vst3 dragonfly-reverb-vst3` too): scanning in a child process (`scan.rs`), plugin nodes (`node.rs`, `host.rs`) over one shared bridge (`bridge.rs`: buffers, event merge, transport, quiet state; `tests/quiet.rs`), the `Catalog` that registers them, the shared plugin thread (`thread.rs`) and editor windows (`window/`). `examples/test_plugin.rs` is a small CLAP plugin the tests load; `tests/real_plugins.rs` uses real ones if installed (`apt-get install dpf-plugins-clap lsp-plugins-clap dragonfly-reverb-clap xvfb`; editors need `xvfb-run`). After editing the example plugin run `cargo build -p noodle-plugins --examples`: `cargo test --test x` doesn't rebuild it. |
| `noodle-eval` | Warp quality metrics (M8): Roberts and Paliwal features (`phasiness.rs`, `spectral.rs`, `transient.rs`) plus onset timing and drift (`timing.rs`), pitch (`pitch.rs`), BS.1770 loudness (`level.rs`) and stereo (`stereo.rs`). Callers give the `TimeMap` from the song's known source and target tempo maps. `evaluate` scores a reference/test pair. `probe.rs` (short controlled signals, rendered natively at any tempo map), `song/` (the five generated songs: patterns, instruments as groups of primitive nodes, the project builder; `songs/*.ron` are their projects, kept in step by `tests/songs.rs`), `tempo.rs` (the target tempo grid), `harness.rs` (warps a probe through the real engine and scores it native, source and round trip) and `table.rs` (rank summary, diff against `baseline/probes.json`), `tests/gate.rs` (the CI gate on the probes against the reference numbers in `baseline/borrowed.json`; `baseline/gate.json` lists the cells that are worse today, `UPDATE_GATE=1` rewrites it), `refs.rs` and `borrowed.rs` (borrowed truth: reference stretchers Rubber Band, SoundTouch and Signalsmith, their measured delay removed, scores against their spread; clips from `eval/local` and `eval/fetch.sh`, `baseline/borrowed.json`). The `noodle-eval` binary has `compare`, `validate` (correlation with the TSM listening-test dataset), `probes`, `songs` and `borrowed`; see its README. Dev tool; nothing else depends on it. |
| `noodle-stems` | Stem separation (M10): the `Separator` trait, `FakeSeparator` for tests, the ONNX backend (`onnx.rs`, loads the runtime library at open), the weight download (`model.rs`), and `split` (`split.rs`: writes the stems and residual as WAVs). Used by the app (`session/stems.rs`). |
| `noodle-cli` | The `noodle` command: `render`, `play` (reloads the file when it changes) and `devices`. |
| `noodle-app` | The egui app (M1). `session.rs` owns the project, undo, files and audio; views return `Edit`s. Tests use `egui_kittest`; user actions (drag, click, double click, key press, wheel, dropped files) come from `testkit.rs`, never from a per-module copy. |
